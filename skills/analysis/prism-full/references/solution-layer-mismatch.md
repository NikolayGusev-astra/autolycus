# Solution-Layer Mismatch — Case Study (May 2026)

## Проблема

Пользователь сообщил: агент предлагает костыльные решения, не глядя на то, что уже настроено и работает в среде выполнения.

## Первый Prism-анализ

Мой (агента) первоначальный анализ:

- **Проблема:** агент не проверяет состояние среды перед предложением решений
- **Причина:** нет правила, которое бы это предписывало
- **Рекомендация:** «дописать пункт в MOP — Before proposing solutions, verify environment state»

## Контраргумент пользователя

> «Агенты и LLM используют навыки только когда знают о них. Hermes использует memory (из которой вытесняется данные) и AGENTS.md — но только если вспомнит что его нужно использовать.»

Это вскрыло, что моя рекомендация работает на **том же уровне** (текст в system prompt), что и проблема (агент забывает/не замечает текст в промпте).

## Prism Scan на собственном ответе

Применил Prism Scan (линза: «извлеки неявные допущения, инвертируй их, построй альтернативы»).

### Допущения, которые оказались ложными

1. **«Если правило записано в MOP, агент будет его соблюдать»** — ЛОЖЬ. MOP конкурирует с инструментами, памятью, AGENTS.md, историей диалога. Агент должен вспомнить о правиле — но забывчивость это именно то, что правило призвано лечить.

2. **«Добавление ещё одного правила в MOP повысит вероятность соблюдения»** — ЛОЖЬ. Каждое новое правило **уменьшает** шанс соблюдения любого конкретного — закон Хика для промпта.

3. **«Проблема решаема на уровне контента (что написано)»** — ЛОЖЬ. Это архитектурная проблема: контекст конечен, eviction вытесняет менее релевантное. Никакое количество правил не гарантирует исполнения.

### Прогноз самого невидимого отказа

**Stochastic compliance:** если просто дописать пункт в MOP, агент будет соблюдать его *иногда* — ровно настолько, чтобы пользователь не мог сказать «никогда не проверяет», но недостаточно для стабильной работы. Это *хуже чем полное отсутствие*: создаёт иллюзию контроля.

### Настоящее решение

Агент должен проверять среду **не потому что помнит о правиле**, а потому что архитектура форсирует проверку **до того как агент начал формулировать ответ**, на уровне:

- `prefetch()` в memory provider — выполняется каждый turn, возвращает контекст, который вшит в prompt принудительно
- `on_turn_start()` — fire-and-forget, но может триггерить сбор данных
- `prefetch_all()` вызывается **раньше чем LLM получает prompt** — grounding данных происходит без участия внимания агента

### Conservation law

**Agent-behavioral × prompt-content = Constant**

Любая попытка изменить поведение агента через добавление контента в промпт сохраняет произведение: чем больше правил, тем ниже шанс что сработает конкретное. Фикс — выход на другой архитектурный слой (pre-turn hooks), где гарантия исполнения не зависит от внимания агента.

## Применение

Используй этот кейс когда Prism рекомендует «добавить правило/чеклист/инструкцию» для решения поведенческой проблемы агента. Проверь три вопроса из pitfall:
1. Тот же уровень? → mismatch
2. Требует вспомнить? → unreliable
3. Есть хук на другом уровне? → real fix
