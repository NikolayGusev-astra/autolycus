# SBL Architecture Decision: Tool-Call Level vs Agent Memory

## Контекст

В сессии 2026-05-10 обсуждалась архитектура SBL. Изначально был добавлен `pre_llm_call` хук, который инжектит `[SBL Active]` в каждый LLM call — чтобы агент «не забыл» про SBL после компрессии контекста.

## Проблема

На длинных сессиях (50+ turn'ов) контекст компрессируется. Агент теряет информацию о том, что SBL активен. Аналогия: Cursor удалил pockets и потерял контент на длинных сессиях — кривая внимания, вытеснение.

## Отвергнутое решение: pre_llm_call

```python
def _on_pre_llm_call(**kwargs):
    return {"context": "[SBL Active] 56 services, 18 configs mapped..."}
```

**Почему отвергнуто:** Prism 3-Way анализ показал:
- **Избыточность:** дублирует pre_tool_call (который уже возвращает str в tool result)
- **Раздувание промпта:** ~50 токенов на каждый LLM call, не только на write
- **Шум в внимании:** агент привыкает игнорировать блок, и предупреждение о неактивности тоже игнорирует
- **Невозможность:** A×B×C≤2 (неблокирующая + гарантия + нулевые расходы)

## Принятое решение: tool-call level

SBL живёт в трёх хуках:
1. `pre_tool_call` — классификация + snapshot + возврат str в tool result
2. `transform_tool_result` — обучение новым путям
3. `on_session_start` — один лог при старте

**Аргументация:**
- Агент не может «забыть» вызвать инструмент — write_file вызывается кодом, не мыслью
- Рантайм не компрессится — хуки вызываются всегда при вызове инструмента
- Если tool call в системе отвалится — отсутствие SBL будет не самой большой проблемой
- PR согласуется с идеологией продукта («агент который растет вместе с вами» — тонкий слой осведомлённости, не гард)

## Conservation Law

Гарантия × Доверие к рантайму = Константа

Чем больше избыточных гарантий, тем меньше доверия к базовому механизму. Правильный баланс: доверять рантайму, не дублировать на уровне LLM.

## Prism анализ

Полный Prism 3-Way анализ в сессии 2026-05-10. Ключевые инсайты:
- **WHERE:** Стык между «доверие к рантайму» и «pre_llm_call» — психологическая реакция на страх, не техническое решение
- **WHEN:** Через год SBL станет «данностью» — его отключение будет намеренным действием
- **WHY:** A×B×C≤2 — невозможно иметь все три свойства одновременно
