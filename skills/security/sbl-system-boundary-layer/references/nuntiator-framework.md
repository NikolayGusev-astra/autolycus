# Nuntiator Framework — Epistemic Enforcement Chain

## Origins

Архитектурный паттерн, рождённый из двух независимых реализаций:
1. **SBL** (системная эпистемология) — знать свой сервер, не гадать
2. **RBE** (доменная эпистемология) — знать свой домен, не тыкать curl вслепую

Обе решают одну и ту же задачу: принудить агента к знанию перед действием. Обе реализованы через хуки, не промпты. Обе столкнулись с одним и тем же законом сохранения.

Отсюда — идея единого фреймворка: **Nuntiator** (лат. «глашатай, напоминатель» — отсылка к рабу Цезаря, шептавшему «memento mori»).

## Принцип

Одна цепь хуков `pre_tool_call`, в которую регистрируются Nuntiatores с разными уровнями привилегий. Каждый Nuntiator может:
- **Пропустить** (passthrough) — вернуть None
- **Заблокировать** (block) — вернуть строку с объяснением
- **Направить** (inject) — инжектить guidance в pre_llm_call

Выполнение — по убыванию privilege. Высший приоритет решает первым. Низший не может отменить решение высшего.

## Державинская иерархия

От «бога» до «червя» — аллюзия на оду Г.Р. Державина «Бог» (1784):

> *Я царь — я раб — я червь — я бог!*

| Уровень | Privilege | Державин | Компонент | Что делает |
|---------|-----------|----------|-----------|------------|
| **Tirith** | 100 | бог | `plugins/sanitize_mcp/` | Целостность — нельзя сломать, нельзя переопределить. Выполняется первым. |
| **Ultra Governance** | 50 | царь | `plugins/ultra_governance/` | Строгие политики — блокирует опасные паттерны поведения |
| **Governance** | 40 | — | `plugins/governance/` | Обычные правила поведения |
| **SBL** | 30 | — | `plugins/sbl/` ✅ | Системная эпистемология: FHS-классификация, снапшот сервисов |
| **RBE** | 20 | червь | `plugins/rtk/strategies/` | Доменная эпистемология: research-before-execute |
| **Observer** | 0 | раб | — | Только смотрит и логирует. Никогда не блокирует. |

## Dual-Layer Design

Каждый Nuntiator может реализовывать два слоя:

1. **pre_tool_call** (блокирование) — Python-код проверяет tool_name + args, принимает решение
2. **pre_llm_call** (направление) — инжектит короткий префикс в system prompt перед генерацией

Оба необходимы: блокировка без направления = ступор агента, направление без блокировки = игнорирование через 2 шага.

## conservation law

**Persistence × ModelAgnostic × ZeroCost ≤ 2**

Любой Nuntiatior может получить любые два, но не все три:
- Persistence + ZeroCost → работает только внутри Hermes/Autolycus (ModelAgnostic потерян)
- Persistence + ModelAgnostic → требует постоянного LLM-вызова (ZeroCost потерян)
- ZeroCost + ModelAgnostic → в промпте, забывается через 150K токенов (Persistence потерян)

SBL и RBE выбрали Persistence + ZeroCost.

## Architectural Invariant

«Модель не может сломать guardrail через RBE» — гарантия достигается порядком выполнения:
1. Tirith (100) вызывается первым
2. Если Tirith заблокировал — RBE (20) даже не видит вызов
3. Модель не может «убедить» RBE ослабить Tirith — Tirith на уровне кода

Это свойство — **монотонность блокировок**: privilege-level chain гарантирует, что lower-privilege guards могут только добавить ограничения, но не снять.

## When to Add a New Nuntiator

Симптом: поведенческое правило, которое агент систематически забывает через N тысяч токенов.

Не пиши его:
- В систему промптов (забудется)
- В memory (забудется после компрессии)
- В skills (то же самое)
- Как независимый plugin (нарушит цепь привилегий)

Пиши как Nuntiator в единую цепь.
