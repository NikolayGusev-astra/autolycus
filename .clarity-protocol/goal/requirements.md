# Requirements Analysis — PGB Law AI Lawyer System

## Функциональные требования

### FR-1: Двухконтурная архитектура
- **Описание:** Система состоит из физически разделённых внутреннего и внешнего контуров
- **Детали:** Внутренний — сервер PGB Law, внешний — VPS в нейтральной юрисдикции
- **Источник:** ТЗ §2.1, Архитектура §2
- **Критерий приёмки:** Документы клиентов физически не передаются во внешний контур
- **Приоритет:** MUST HAVE (не подлежит обсуждению)

### FR-2: Intake-протокол
- **Описание:** Обязательный чек-лист сбора данных перед началом работы
- **Детали:** Классификация задачи, проверка полноты, запрос недостающего, подтверждение готовности
- **Источник:** Конституция §3, ТЗ §3.1
- **Критерий приёмки:** Система не переходит к анализу без завершения Intake
- **Приоритет:** MUST HAVE

### FR-3: Обезличивание подзапросов
- **Описание:** Замена идентифицирующих маркеров на абстрактные роли/категории
- **Правила:** Удаление ФИО, юрлиц, сумм, дат, географии с сохранением правовой сути
- **Контроль:** Опциональная ручная проверка для HNWI/Forbes/резонансных дел
- **Источник:** Конституция §11.4
- **Критерий приёмки:** Подзапрос проходит «правило семинара» — мог бы быть задан на конференции
- **Приоритет:** MUST HAVE (критический компонент)

### FR-4: Работа с внешним AI (Claude)
- **Описание:** Отправка обезличенных подзапросов → получение ответов → применение к фактуре
- **Ограничения:** Только Claude API, только через защищённую обвязку, только обезличенные запросы
- **Источник:** ТЗ §2.2, Конституция §11
- **Критерий приёмки:** Полный data flow работает end-to-end
- **Приоритет:** MUST HAVE

### FR-5: Сборка финального продукта
- **Описание:** Применение абстрактных ответов Claude к конкретной фактуре дела
- **Детали:** Подстановка реальных имён, сумм, реквизитов; Self-review по чек-листу
- **Источник:** Конституция §9, ТЗ §3.5
- **Критерий приёмки:** Куратор получает готовый документ с указанием источников и уровня уверенности
- **Приоритет:** MUST HAVE

### FR-6: RAG-база знаний
- **Описание:** Векторный поиск по внутренним документам Бюро, шаблонам, выгрузкам КП
- **Источники:** Архив PGB Law, выгрузки КонсультантПлюс, внутренняя доктрина
- **Требования:** Локальная векторная база, метаданные, изоляция по делам
- **Источник:** ТЗ §3.2, Архитектура §2
- **Критерий приёмки:** Поиск релевантных документов < 3 сек, Precision@5 > 80%
- **Приоритет:** MUST HAVE

### FR-7: Интеграция с КонсультантПлюс
- **Описание:** Получение нормативки и судебной практики
- **Ограничения:** Только гибридный workflow (человеческая выгрузка) + опционально API
- **Источник:** ТЗ §3.3, Архитектура §3
- **Критерий приёмка:** ИИ-юрист формирует запрос → помощник выгружает → система индексирует
- **Приоритет:** MUST HAVE (гибридный)

### FR-8: Интеграция с Casebook
- **Описание:** Проверка контрагентов, конфликт интересов, due diligence
- **Ограничения:** API (приоритет) или гибридный workflow (резерв). Headless browser запрещён!
- **Источник:** ТЗ §3.3-бис, Конституция §5-бис
- **Приоритет:** MUST HAVE для модуля КП; SHOULD HAVE для работы по делу

### FR-9: Модуль КП и оценка трудозатрат
- **Описание:** Автоматическая подготовка коммерческих предложений на основе ProjectMate
- **Детали:** Поиск аналогов, статистическая оценка, расчёт стоимости, генерация КП
- **Источник:** ТЗ §3.8, Конституция §12
- **Критерий приёмки:** КП готово за < 30 мин (для типовых дел), точность оценки ±30%
- **Приоритет:** MUST HAVE

### FR-10: Self-review
- **Описание:** Автоматическая проверка результата по чек-листу перед выдачей Куратору
- **Чек-лист:** Ссылки на практику подтверждены, нормы актуальны, факты привязаны, источники указаны
- **Источник:** Конституция §4.6, §11.8
- **Приоритет:** MUST HAVE

### FR-11: Аудит-лог
- **Описание:** Полное логирование всех действий системы
- **Детали:** Каждое обращение к Claude → дата, дело, запрос, ответ, подтверждение
- **Источник:** Архитектура §3.4, Конституция §11.12
- **Критерий приёмки:** Куратор может восстановить полную цепочку любого вывода
- **Приоритет:** MUST HAVE

### FR-12: Интерфейс
- **Описание:** Веб-интерфейс для Куратора, помощника, администратора
- **Сценарии:** Создание дела, постановка задачи, просмотр обезличенных запросов, приёмка результата
- **Источник:** ТЗ §4
- **Приоритет:** MUST HAVE

## Нефункциональные требования

### NFR-1: Безопасность
- **Адвокатская тайна:** Ст. 8 ФЗ №63-ФЗ, КПЭА п.1 ст.6
- **Трёхуровневая защита:** Содержание + инфраструктура + архитектура
- **Изоляция дел:** Куратор А не видит дела Куратора Б
- **Шифрование БД:** На уровне диска и при передаче

### NFR-2: Конфиденциальность интеграций
- **Claude:** Анонимный аккаунт, оплата через реселлер, VPS в нейтральной юрисдикции
- **Casebook:** Без headless browser, без автоматизации логина
- **КонсультантПлюс:** Без прямого извлечения БД

### NFR-3: Производительность
- **Ответ системы:** < 5 минут для типового запроса (без учёта Claude roundtrip)
- **RAG-поиск:** < 3 сек
- **Контекстное окно LLM:** ≥ 128K токенов

### NFR-4: Надёжность
- **Работа при недоступности Claude:** Деградация функциональности без остановки
- **Резервное копирование:** Шифрованное, локальное
- **Аптайм сервера:** 24/7 (стандарт для внутренней инфраструктуры)

### NFR-5: Ремонтопригодность
- **Выбор фреймворка оркестрации:** LangGraph или n8n (не vendor lock-in)
- **Модель LLM:** Заменяема (контейнеризированный inference)
- **Версионирование:** Конституция версионируется

### NFR-6: Юридическая соответствие
- **Только Claude:** Запрет на GPT, Gemini, поисковые системы, соцсети
- **Без нарушения лицензий:** КонсультантПлюс, Casebook
- **Zero Data Retention:** Целевой, но необязательный режим с Anthropic
- **Ответственность:** Куратор подписывает — Куратор отвечает
