# Solution Analysis — PGB Law AI Lawyer System

## Архитектурное решение (из ТЗ)

### Вариант, выбранный заказчиком: Двухконтурная архитектура с локальной LLM + Claude API

```
[Внутренний контур: сервер PGB Law]
  Куратор → Веб-интерфейс → Локальная LLM
                              ↕
                         RAG-база (Qdrant)
                              ↕
                     КонсультантПлюс (выгрузки)
                              ↕
                          ProjectMate
                              ↕
                          Casebook (API/гибрид)
                              ↕
                    Аудит-лог (БД + файлы)
                              ↓
                    [Только обезличенные подзапросы]
                              ↓
[Защищённая обвязка: VPS + reseller API]
                              ↓
[Внешний контур: Claude API]
                    Только абстрактные правовые вопросы
                    Никаких имён, сумм, реквизитов
```

## Альтернативные варианты, которые рассматривались (или должны быть рассмотрены)

### Альтернатива 1: Только Claude (без локальной LLM)
- **Описание:** Весь интеллект во внешнем контуре, тонкая настройка обезличивания на стороне клиента
- **Плюсы:** Проще реализовать, лучшее качество рассуждений
- **Минусы:** Один контур = нет гарантии конфиденциальности
- **Причина отклонения:** Нарушение требований адвокатской тайны — запросы идут с pgblaw.ru домена, все обращения привязаны к аккаунту юрлица

### Альтернатива 2: Только локальная LLM (без Claude)
- **Описание:** Qwen 72B / DeepSeek V3 справляется со всеми задачами
- **Плюсы:** Полная автономия, нет зависимости от внешних сервисов, максимальная безопасность
- **Минусы:** Заметно худшее качество юридических рассуждений, особенно по сложным/уникальным вопросам
- **Причина отклонения:** Клиенты PGB Law — уровень Forbes; качество должно соответствовать

### Альтернатива 3: Локальная fine-tuned модель на юридических данных
- **Описание:** Qwen 72B + fine-tuning на документах PGB Law
- **Плюсы:** Может приблизить качество к Claude по специфике Бюро
- **Минусы:** Стоимость fine-tuning, сложность обновления, риск утечки данных при fine-tuning (Catastrophic forgetting + memorization)
- **Статус:** Рассмотреть как фазу 2 после запуска MVP

### Альтернатива 4: Использование российских AI-сервисов (GigaChat, YandexGPT)
- **Описание:** Внешний контур через российского провайдера
- **Плюсы:** Нет проблем с санкциями, оплата в рублях
- **Минусы:** Качество юридических рассуждений хуже Claude/ChatGPT; данные на серверах российского юрлица (также требует двухконтура); привязка к аккаунту
- **Причина отклонения:** Заказчик явно указал цель — топовое качество рассуждений, а Claude эталон

## Выбранное решение: Обоснование

Заказчик выбрал гибридную архитектуру, потому что:

1. **Правовое ограничение — константа:** Адвокатская тайна не может быть нарушена ни при каком масштабе → двухконтурность обязательна

2. **Качественное ограничение — реальность рынка:** Клиенты уровня Forbes ожидают качества «партнёр с 20-летним опытом» → нужен Claude или эквивалент

3. **Компромисс:** Локальная LLM делает всю «грязную работу» (обезличивание, сборку, self-review), Claude даёт «тонкое рассуждение» на абстрактных вопросах

## Ключевые компоненты решения

### 1. Оркестрация workflow
- **Рекомендация:** LangGraph (агентный DAG с точками human-in-the-loop)
- **Обоснование:** Intake → декомпозиция → обезоживание → отправка → получение → сборка = классический DAG с условными переходами
- **Human-in-the-loop:** Подтверждение готовности после Intake, подтверждение обезличенных подзапросов для HNWI-дел, финальная подписка Куратора

### 2. Локальная LLM
- **Кандидаты для тестирования:** Qwen 2.5 72B, DeepSeek V3, Llama 3.3 70B
- **Критерий выбора:** Качество на русском + следование длинному system prompt (Конституция) + RAG + обезличивание
- **Железо:** 1-2x GPU A6000 (48GB VRAM) или H100 (если бюджет позволяет)

### 3. RAG-система
- **Векторная база:** Qdrant (локальный, высокая производительность на русском)
- **Embedding-модель:** BGE-M3 или multilingual-e5-large (с тестированием на юридических текстах)
- **Изоляция:** Поиск с фильтром по № дела + проверка прав доступа

### 4. Защищённая обвязка для Claude
- **Reseller:** ProxyAPI или Vsegpt (оплата в рублях, без привязки к PGB Law)
- **VPS:** Нидерланды или Германия (нейтральная юрисдикция, GDPR)
- **Аккаунт:** Отдельный email не на pgblaw.ru, не на имя Бюро
- **Аудит:** Локальное логирование + невозможность удаления постфактум

### 5. Модуль КП (ProjectMate integration)
- **Интеграция:** Периодическая выгрузка (раз в месяц) + нормализация свободного текста LLM
- **Расчётный движок:** Медиана + перцентили по аналогам, поправки на специфику
- **Генерация КП:** Тезисная основа (локально) + шлифовка через Claude (обезличенная) + стилистика PGB Law

## Составляющие MVP vs Фаза 2

### MVP (обязательно к запуску)
1. Локальная LLM + Конstitution (system prompt)
2. Intake-протокол
3. RAG на базовых документах (50-100 типовых кейсов)
4. Двухконтурная архитектура с Claude (обезличивание)
5. Self-review
6. Аудит-лог
7. Веб-интерфейс (создание дела, постановка задачи, просмотр результата)

### Фаза 2 (следующие 3-6 месяцев)
1. Полная RAG-база (все архивы)
2. Модуль КП + ProjectMate
3. Интеграция с Casebook
4. Гибридный workflow с КонсультантПлюс
5. Расширенные форматы документов (договоры, корп. документы)
6. Цикл обратной связи (калибровка модели)
