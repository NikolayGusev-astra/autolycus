## Детальный анализ критических отказов

### F-01: Утечка идентифицирующих данных через ненадёжное обезличивание

**Цепочка отказа:**
1. Начальное состояние: Локальная LLM получает задачу с конкретной фактурой
2. Триггер: LLM недостаточно качественно обезличивает подзапрос (пропускает уникальные обстоятельства, «говорящие» детали)
3. **Вред начинается:** В Claude уходит запрос, по которому можно идентифицировать дело
4. Распространение: Anthropic хранит запрос 30 дней (или дольше); при утечке изAnthropic → оппонент получает стратегию стороны
5. **Точки вмешательства:**
   - **Профилактика:** Трёхуровневая проверка обезличивания (LLM → regex/правила → Куратор для HNWI)
   - **Обнаружение:** Аудит-лог + регулярный аудит Куратором
   - **Смягчение:** VPS в нейтральной юрисдикции + анонимный аккаунт (нет привязки к PGB Law)
   - **Восстановление:** При обнаружении утечки — расследование через аудит-лог, уведомление пострадавших

**干预 points:**
- Обязательная ручная проверка для HNWI/Forbes/резонансныхдел (уже предусмотрено)
- Автоматический detectоr на основе второго прохода: «содержит ли этот текст идентифицирующие данные?»
- Red teaming обезличивания перед запуском

### F-03: Галлюцинация — выдуманная практика/норма

**Цепочка отказа:**
1. Начальное состояние: ИИ работает без жёсткой привязки к источникам
2. Триггер: Неоднозначная правовая ситуация + давление на скорость → ИИ «дополняет» практику
3. **Вред начинается:** Куратор видит «уверенный» вывод с фиктивной ссылкой на практику
4. Распространение: Куратор включает выдуманную практику в правовую позицию → суд отклоняет → репутационные потери + проигрыш дела
5. **Точки вмешательства:**
   - **Профилактика:** Self-review чек-лист (все ссылки на практику должны быть подтверждены документами в контексте)
   - **Обнаружение:** Маркировка источников в финальном продукте («[RAG арт. 12.1 ГК РФ]» вместо «по общему правилу»)
   - **Смягчение:** Guardrails блокируют выдачу без подтверждённых ссылок
   - **Восстановление:** При обнаружении — пересмотр процедуры индексации, дообучение/модификация промпта

---

### F-04: Неприменимый ответ Claude → слепое применение Куратором

**Цепочка отказа:**
1. Начальное состояние: Claude отвечает на абстрактный вопрос → получает общую позицию
2. Триггер: Куратор не замечает, что общая позиция не учитывает специфику дела (которую он не передавал Claude)
3. **Вред начинается:** Куратор применяет общий ответ к конкретной фактуре без адаптации
4. Распространение: Неадаптированная позиция попадает в процессуальный документ → суд указывает на несоответствие
5. **Точки вмешательства:**
   - **Профилактика:** Маркировка в финальном продукте: «[Источник: внешний AI, требует проверки на соответствие фактуре]»
   - **Обязательное поле:** «Уровень уверенности» + «Слабые места позиции» в каждом выводе
   - **Смягчение:** Self-review проверяет соответствие ответа фактуре дела

### F-08: Подрядчик получает доступ к данным

**Цепочка отказа:**
1. Начальное состояние: Подрядчик настраивает/отлаживает систему на сервере Бюро
2. Триггер: Отсутствие технической изоляции между средой разработки и продуктивной средой
3. **Вред начинается:** Подрядчик видит реальные дела клиентов уровня Forbes
4. Распространение: Утечка через подрядчика → репутационный ущерб + правовые последствия
5. **Точки вмешательства:**
   - **Профилактика:** NDA + разработка на синтетических данных + доступ к продуктиву только через аудитируемые логи
   - **Обнаружение:** Аудит-лог фиксирует все обращения к данным
   - **Смягчение:** Техническая поддержка без доступа к содержанию (только инфраструктура)

### F-10: Неточная оценка трудозатрат в КП

**Цепочка отказа:**
1. Начальное состояние: ProjectMate содержит данные по прошлым проектам с свободным текстом
2. Триггер: Нормализация свободного текста неточна → неверная классификация аналогов
3. **Вред начинается:** Система даёт прогноз 40 часов, реально нужно 120
4. Распространение: Бюро берёт проект по фиксированной цене → убытки; или завышает цену → теряет клиента
5. **Точки вмешательства:**
   - **Профилактика:** Вилка (P25-P75) вместо точечной оценки; ручная проверка Куратором
   - **Обнаружение:** Цикл обратной связи — сравнение факта с прогнозом
   - **Смягчение:** Варианты ценообразования (фиксированная / поэтапная / cap fee)
